## Contract and SDK discrepancy

There is one policy per tenant. The beta resource reference documents **Get** and **Update**, with no creation or deletion operation. GET returns an object with no `id` in its documented response. Use `/beta/policies/adminConsentRequestPolicy` throughout. [Resource reference](https://learn.microsoft.com/en-us/graph/api/resources/adminconsentrequestpolicy?view=graph-rest-beta), [GET](https://learn.microsoft.com/en-us/graph/api/adminconsentrequestpolicy-get?view=graph-rest-beta).

The beta update reference and its Microsoft-owned Markdown source specify **PUT**, JSON content, all five writable properties, and **204 No Content**. GET returns **200**. Least-privilege application permissions are `Policy.Read.All` for GET and `Policy.ReadWrite.ConsentRequest` for update; the write permission also authorizes reads. Delegated operations require an appropriate Entra role. [Update reference](https://learn.microsoft.com/en-us/graph/api/adminconsentrequestpolicy-update?view=graph-rest-beta), [Microsoft documentation source](https://github.com/microsoftgraph/microsoft-graph-docs-contrib/blob/main/api-reference/beta/api/adminconsentrequestpolicy-update.md), [GET permissions](https://learn.microsoft.com/en-us/graph/api/adminconsentrequestpolicy-get?view=graph-rest-beta).

The current public beta OpenAPI contradicts that REST contract: its route exposes GET, PATCH with a generic successful model response, and DELETE 204, with **no PUT**. The pinned beta Go SDK `v0.168.0` reproduces those methods. This explains the SDK mismatch; generated method presence does not establish actual service support. Neither source discrepancy justifies switching to v1.0. [Current beta OpenAPI](https://github.com/microsoftgraph/msgraph-metadata/blob/master/openapi/beta/openapi.yaml), [Pinned request builder](https://github.com/microsoftgraph/msgraph-beta-sdk-go/blob/v0.168.0/policies/admin_consent_request_policy_request_builder.go).

Implementation recommendation, supported by the parent's beta PUT/PATCH validation below: build the serialized request with `Policies().AdminConsentRequestPolicy().ToPatchRequestInformation(...)`, set `requestInfo.Method = abstractions.PUT`, and send it through `r.client.GetAdapter().SendNoContent(...)` with OData error mapping. This preserves the configured beta base URL, authentication, middleware, and model serialization while honoring the documented verb/bodyless response. Keep Graph calls in CRUD. The repository already overrides request information to PUT for device registration policy. [Kiota request information](https://github.com/microsoft/kiota-abstractions-go/blob/v1.12.1/request_information.go), [Existing PUT adaptation](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/resources/identity_and_access/graph_beta/device_registration_policy/crud.go).

## Writable shape and import compatibility

| Terraform field | Graph field/type | Recommended treatment |
| --- | --- | --- |
| `is_enabled` | `isEnabled`, Boolean | Required; preserve explicit false. |
| `notify_reviewers` | `notifyReviewers`, Boolean | Required; preserve explicit false. |
| `reminders_enabled` | `remindersEnabled`, Boolean | Required; preserve explicit false. |
| `request_duration_in_days` | `requestDurationInDays`, Int32 | Required; preserve zero; no invented default. |
| `reviewers` | `reviewers`, reviewer scope collection | Required collection; allow explicit empty collection. |
| `version` | `version`, Int32 | Computed and read-only; omit from writes. |

The update reference requires the five writable fields. Current beta CSDL marks the three Booleans, duration, and version nonnullable and models reviewers as a collection. The resource reference identifies version as changing when the policy changes. No duration maximum, minimum, reviewer count limit, or reviewer nonempty constraint was found in those sources. [Update contract](https://learn.microsoft.com/en-us/graph/api/adminconsentrequestpolicy-update?view=graph-rest-beta), [Current beta production CSDL](https://github.com/microsoftgraph/msgraph-metadata/blob/master/schemas/beta-Prod.csdl), [Policy properties](https://learn.microsoft.com/en-us/graph/api/resources/adminconsentrequestpolicy?view=graph-rest-beta).

The **official GET example** is `isEnabled=false`, `notifyReviewers=false`, `remindersEnabled=false`, `requestDurationInDays=0`, `version=0`, `reviewers=[]`. Generated imports must preserve that representable state: a duration minimum of 1 or required reviewer count of 1 would invalidate documented tenant state. This read example alone does not prove every combination is accepted by PUT. [GET example](https://learn.microsoft.com/en-us/graph/api/adminconsentrequestpolicy-get?view=graph-rest-beta).

Use a nonnil empty SDK reviewer slice to send `[]`: the pinned model skips reviewers when its slice is nil. Map an empty remote collection into an empty Terraform collection, preserving the difference from unknown/null. SDK policy getters use `*bool`, `*int32`, and `[]AccessReviewReviewerScopeable`; its inherited `GetId()` is not evidence the endpoint returns an ID. [Pinned policy model](https://github.com/microsoftgraph/msgraph-beta-sdk-go/blob/v0.168.0/models/admin_consent_request_policy.go).

## Reviewer queries and validators

The consent-policy update example uses objects containing `query: "/users/{user-id}"` and `queryType: "MicrosoftGraph"`, omitting `queryRoot`. The generic reviewer-scope type defines `query` as the reviewer selection, `queryType` as an open string with examples `MicrosoftGraph` and `ARM`, and optional `queryRoot` for resolving relative queries; `decisions` is its documented value. All three are nullable strings in current CSDL, rather than enums. [Consent update example](https://learn.microsoft.com/en-us/graph/api/adminconsentrequestpolicy-update?view=graph-rest-beta), [Reviewer-scope properties](https://learn.microsoft.com/en-us/graph/api/resources/accessreviewreviewerscope?view=graph-rest-beta), [CSDL](https://github.com/microsoftgraph/msgraph-metadata/blob/master/schemas/beta-Prod.csdl).

The generic access-review guide demonstrates users, group transitive members, group owners, application owners, and `./manager` with `queryRoot="decisions"`. It also shows `./owners` without queryRoot. Therefore a blanket validator requiring queryRoot for every relative query would contradict Microsoft's examples. These are **access-review** examples, not proof all patterns work for admin consent policies. The Entra consent-workflow UI supports users, groups, and roles but does not specify their Graph query syntax. [Access-review examples](https://learn.microsoft.com/en-us/graph/accessreviews-reviewers-concept), [Consent-workflow configuration](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-admin-consent-workflow).

Recommendation: support `query`, `query_type`, and optional `query_root` as strings; never supply a default queryRoot. If requiring query/query_type for the Terraform query-based surface, document that as the supported configuration shape rather than claiming metadata requires them. Avoid UUID-only query validation, treating `queryType` examples as an exhaustive enum, or allowing only `/users/...` without target-specific evidence. Generic beta models also expose `reviewerId` and `scopeType`; target-specific use of those newer alternatives remains unverified. [Reviewer model](https://github.com/microsoftgraph/msgraph-beta-sdk-go/blob/v0.168.0/models/access_review_reviewer_scope.go), [Reviewer-scope reference](https://learn.microsoft.com/en-us/graph/api/resources/accessreviewreviewerscope?view=graph-rest-beta).

## Singleton lifecycle, version, and shared utilities

Use the stable Terraform identifier/import literal `adminConsentRequestPolicy`; it identifies the tenant singleton rather than a service-returned ID. Validate that import literal and assign it after successful reads/writes. Create adopts/configures the existing object by PUT. Destroy should remove Terraform state and retain the tenant policy, matching authorization policy, security defaults, and SharePoint settings. Do not infer supported deletion from the generated SDK/OpenAPI DELETE. [Security-defaults ID/import convention](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/resources/identity_and_access/graph_beta/security_defaults_enforcement_policy/resource.go), [Authorization-policy Delete](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/resources/identity_and_access/graph_beta/authorization_policy/crud.go), [SharePoint-settings Delete](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/resources/m365_admin/graph_beta/sharepoint_settings/crud.go).

Keep `version` Computed without `UseStateForUnknown`: a mutable version must remain unknown during an update so the refreshed increment is legal. Use that modifier for constant `id`. Exclude version from write-consistency comparisons; compare only managed writable values. [HashiCorp plan modification](https://developer.hashicorp.com/terraform/plugin/framework/resources/plan-modification), [Version semantics](https://learn.microsoft.com/en-us/graph/api/resources/adminconsentrequestpolicy?view=graph-rest-beta).

Reuse shared Bool/Int32/String conversions, `commonschema.ResourceTimeouts`, `crud.HandleTimeout`, `crud.ReadWithRetry` and response containers, and shared Kiota error handling. A successful but stale GET needs `ConsistencyPredicate` to wait for the managed values; default retries alone stop after any successful read. Existing authorization-policy CRUD/predicate provide that pattern. Additional consecutive matching reads should be driven by observed target behavior. [Converters](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/common/convert/framework_to_graph.go), [Common timeout schema](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/common/schema/timeouts.go), [Retry options](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/common/crud/read_with_retry.go), [Consistency pattern](https://github.com/deploymenttheory/terraform-provider-microsoft365/blob/d206ea3ad65de70cd1852eb622070189db0f893d/internal/services/resources/identity_and_access/graph_beta/authorization_policy/predicate.go).

## Parent runtime validation

The parent ran `Test-AdminConsentRequestPolicyBeta.ps1` using the `identity_and_access` credentials against `/beta/policies/adminConsentRequestPolicy`. The captured sequence establishes GET 200, identical-value PUT 204 with no response body, identical-value PATCH 404, and subsequent GET 200. Both write requests captured immutable `request_json` strings containing all five writable fields: `isEnabled=false`, `notifyReviewers=false`, `remindersEnabled=false`, `requestDurationInDays=0`, and `reviewers=[]`. The final read preserved those original writable values and the artifact records `configuration_preserved=true`. No DELETE was attempted. [Parent runtime evidence](C:/Users/Dafydd/github/deploymenttheory/local_testing/local_testing/environment/windows/msgraph/identity_and_access/admin-consent-request-policy-beta-4894.json).

This validates the beta SDK/PATCH mismatch and confirms that PUT accepts the observed disabled/zero/empty configuration. Keep beta PUT through the request-method override; a stable-version fallback is unnecessary. These probes do not establish support for every duration/reviewer combination, nonempty reviewer query variants, or deletion. Policy version may legitimately advance on a write and is excluded from preservation of writable configuration; the captured sequence happened to retain version 0. [Parent runtime evidence](C:/Users/Dafydd/github/deploymenttheory/local_testing/local_testing/environment/windows/msgraph/identity_and_access/admin-consent-request-policy-beta-4894.json), [Documented version semantics](https://learn.microsoft.com/en-us/graph/api/resources/adminconsentrequestpolicy?view=graph-rest-beta).

Still unresolved: target-specific nonempty reviewer query/root/type restrictions and duration bounds, normalization/order of reviewer entries, other enabled/duration/reviewer combinations, and propagation timing after actual configuration changes. The identical-value probe does not measure those behaviors.
