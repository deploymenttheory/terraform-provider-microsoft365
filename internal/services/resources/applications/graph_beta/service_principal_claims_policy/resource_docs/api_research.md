## Contract and unresolved lifecycle

The target is the **single custom claims policy contained by a service principal**, addressed at `https://graph.microsoft.com/beta/servicePrincipals/{service-principal-object-id}/claimsPolicy`. It shares the underlying policy with the Entra portal's additional-claims configuration. It differs from a reusable claims mapping policy; an assigned claims mapping policy supersedes this configuration. One Terraform resource should exclusively own this complete singleton, including claims configured through the portal. [Microsoft claims customization reference](https://learn.microsoft.com/en-us/entra/identity-platform/reference-claims-customization).

| Operation | Documented beta contract | Verification still required |
| --- | --- | --- |
| `GET .../claimsPolicy` | Read policy, `200`. The response prose incorrectly says collection; metadata, SDK and tutorial show a singleton object. | Virgin-policy response; missing parent versus missing policy; returned policy ID. |
| `PUT .../claimsPolicy` | Create if absent or replace existing policy. | **Contradictory documentation:** prose says `204` with a policy body; example says `201 Created` with a body. Capture actual initial/replacement status and body. Establish omitted-field defaults. |
| `PATCH .../claimsPolicy` | Update supplied policy properties; documentation says `201` with body. | Actual status/body, collection replacement, explicit `null`, and omitted-property behavior. |
| `DELETE .../claimsPolicy` | Neither a method on the resource documentation nor an operation in the pinned SDK. | **Server support remains unknown.** Missing SDK/docs does not establish unsupported HTTP DELETE. Probe the actual beta operation and inspect the policy afterward. |

Sources: [GET](https://learn.microsoft.com/en-us/graph/api/customclaimspolicy-get?view=graph-rest-beta), [PUT](https://learn.microsoft.com/en-us/graph/api/serviceprincipal-put-claimspolicy?view=graph-rest-beta), [PATCH](https://learn.microsoft.com/en-us/graph/api/customclaimspolicy-update?view=graph-rest-beta), [resource methods](https://learn.microsoft.com/en-us/graph/api/resources/customclaimspolicy?view=graph-rest-beta).

If beta DELETE is unsupported, choosing explicit retention/state removal, baseline restoration, or a settings-resource lifecycle requires a documented design decision supported by observations; a fabricated reset is not a complete lifecycle.

## Permissions, clouds, identifiers

GET, PUT and PATCH all document `Policy.ReadWrite.ApplicationConfiguration` for application and work/school delegated access, including GET; personal accounts are unsupported. Delegated GET lists Global Reader and Application Administrator, while PUT/PATCH specify Application Administrator as least privileged. The policy APIs support the global cloud only; US Government L4/L5 and China are marked unavailable. These policy permissions are separate from permissions needed to create or delete a fixture application. [GET authorization](https://learn.microsoft.com/en-us/graph/api/customclaimspolicy-get?view=graph-rest-beta), [PUT authorization](https://learn.microsoft.com/en-us/graph/api/serviceprincipal-put-claimspolicy?view=graph-rest-beta), [PATCH authorization](https://learn.microsoft.com/en-us/graph/api/customclaimspolicy-update?view=graph-rest-beta).

Public live [beta metadata](https://graph.microsoft.com/beta/$metadata), fetched successfully during research, defines `claimsPolicy` as `Type="graph.customClaimsPolicy" ContainsTarget="true"`. Recommendation: address/import by **service principal object ID**, require replacement if that parent changes, and retain the returned policy `id` separately if exposed. Do not substitute the application/client ID, application object ID, or assume policy ID equals parent ID. The policy's `id` is server output; the documented writable-body properties exclude it. [Policy resource](https://learn.microsoft.com/en-us/graph/api/resources/customclaimspolicy?view=graph-rest-beta).

## Payload coverage and JSON design

The current public beta metadata and the local `msgraph-beta-sdk-go v0.168.0` agree on four typed policy properties: `audienceOverride`, `claims`, `includeApplicationIdInIssuer`, and `includeBasicClaimSet`. Metadata types `claims` as `Collection(graph.customClaimBase)`, not only `customClaim`. [Microsoft published global beta CSDL](https://github.com/microsoftgraph/msgraph-metadata/blob/master/schemas/beta-Prod.csdl), [pinned SDK model](https://github.com/microsoftgraph/msgraph-beta-sdk-go/blob/v0.168.0/models/custom_claims_policy.go).

The legitimate payload tree includes:

- `customClaim`: name, namespace, token formats (`saml` and/or `jwt`), SAML attribute-name format and configurations. [Type](https://learn.microsoft.com/en-us/graph/api/resources/customclaim?view=graph-rest-beta).
- `samlNameIdClaim`: NameID format, optional service-provider name qualifier and configurations. [Type](https://learn.microsoft.com/en-us/graph/api/resources/samlnameidclaim?view=graph-rest-beta).
- Configuration: optional attribute and condition, plus an **ordered** transformations array. Transform output takes precedence over the attribute; the attribute supplies fallback when there is no transform output. [Configuration](https://learn.microsoft.com/en-us/graph/api/resources/customclaimconfiguration?view=graph-rest-beta).
- Attributes: `sourcedAttribute` (`id`, `source`, `isExtensionAttribute`) or `valueBasedAttribute` (`value`). Sources include user, application, resource, audience and company. [Sourced](https://learn.microsoft.com/en-us/graph/api/resources/sourcedattribute?view=graph-rest-beta), [static](https://learn.microsoft.com/en-us/graph/api/resources/valuebasedattribute?view=graph-rest-beta).
- Conditions: `customClaimCondition` with optional group-membership IDs and user type; null condition is demonstrated in Microsoft's tutorial. [Condition](https://learn.microsoft.com/en-us/graph/api/resources/customclaimcondition?view=graph-rest-beta), [tutorial](https://learn.microsoft.com/en-us/entra/identity-platform/claims-customization-custom-claims-policy).
- Transformations: contains, starts/ends-with, extract/alpha/number/mail-prefix, if-empty/not-empty, join, regex-replace, substring, upper/lowercase and trim. Input may derive from the previous transform; preserving array order matters. [Transformation contract](https://learn.microsoft.com/en-us/graph/api/resources/customclaimtransformation?view=graph-rest-beta), [pinned discriminator factory](https://github.com/microsoftgraph/msgraph-beta-sdk-go/blob/v0.168.0/models/custom_claim_transformation.go).

`groupFilter` is shown in the policy documentation's JSON and tutorial responses but is absent from both the current global beta policy metadata and the pinned SDK's typed accessors; `groupClaimFilterBase` is not defined in the live metadata. Treat its writable shape and behavior as unresolved, preserve observed data, and avoid inventing a restrictive schema. [Resource JSON](https://learn.microsoft.com/en-us/graph/api/resources/customclaimspolicy?view=graph-rest-beta), [tutorial response](https://learn.microsoft.com/en-us/entra/identity-platform/claims-customization-custom-claims-policy).

Recommendation: use a whole-policy JSON object, or typed root controls with lossless JSON for the complete polymorphic subtrees. Validate JSON structure and known property types without arbitrarily rejecting valid attributes, transformation variants, future fields, null conditions, or empty collections. A fully typed nested schema is viable only if all these variants are covered. Ensure any SDK JSON round-trip retains AdditionalData rather than silently dropping unknown content. `audienceOverride` needs a custom signing key to affect tokens, and `includeApplicationIdInIssuer` is relevant only to SAML 2.0 with that key; CRUD storage alone does not prove token behavior. [Policy fields](https://learn.microsoft.com/en-us/graph/api/resources/customclaimspolicy?view=graph-rest-beta).

Semantic equality should ignore whitespace and object-key order, preserve ordered arrays and **preserve `@odata.type` discriminators**. Never copy the synchronization-schema helper's recursive removal of every `@odata.*` key or `version`: that would conceal meaningful policy changes. Remove only proven server-owned root fields/annotations, and normalize missing/null/default values only with API evidence. Microsoft's tutorial returns `includeApplicationIdInIssuer:false` after an omitted input, while the field reference describes a `true` default; do not hardcode a Terraform default before testing. [Tutorial](https://learn.microsoft.com/en-us/entra/identity-platform/claims-customization-custom-claims-policy), [field reference](https://learn.microsoft.com/en-us/graph/api/resources/customclaimspolicy?view=graph-rest-beta).

## SDK and repository fit

Local inspection confirmed `ServicePrincipals().ByServicePrincipalId(id).ClaimsPolicy().Get/Put/Patch`; each returns `CustomClaimsPolicyable`, permits a nil result for an empty successful response, and uses the normal authenticated request adapter. There is no generated Delete. Prefer direct SDK calls in CRUD and a normal GET after successful writes; never depend on a PUT body for identity. If preserving unknown JSON or a verified DELETE requires adapter-level request construction, keep that exception narrow and explicit. [Pinned builder](https://github.com/microsoftgraph/msgraph-beta-sdk-go/blob/v0.168.0/serviceprincipals/item_claims_policy_request_builder.go).

Follow local `internal/services/resources/identity_and_access/graph_beta/conditional_access_policy/{resource,crud,construct,state}.go` for direct SDK calls, shared timeouts/retries, schema helpers and converters. Consult `internal/services/resources/applications/graph_beta/service_principal_synchronization_schema_json/{resource,helpers,construct,state}.go` only for JSON custom-type and semantic-equality mechanics; its schema-reset deletion and normalization rules are endpoint-specific and do not transfer.
