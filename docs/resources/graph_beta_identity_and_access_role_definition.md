# microsoft365_graph_beta_identity_and_access_role_definition (Resource)

Manages custom Microsoft Entra directory role definitions using the `/roleManagement/directory/roleDefinitions` endpoint. Custom roles grant a chosen set of `microsoft.directory/*` resource actions and require Microsoft Entra ID P1 or P2. Built-in roles cannot be managed or imported by this resource.

## Example Usage

### Minimal

```terraform
# Minimal custom directory role: a display name and one set of allowed resource actions.
resource "microsoft365_graph_beta_identity_and_access_role_definition" "application_reader" {
  display_name = "Application Reader"
  is_enabled   = true

  role_permissions = [
    {
      allowed_resource_actions = [
        "microsoft.directory/applications/standard/read"
      ]
    }
  ]
}
```

### Maximal

```terraform
# Custom directory role with every optional attribute set.
# template_id becomes the role definition ID and cannot be changed after creation.
resource "microsoft365_graph_beta_identity_and_access_role_definition" "device_support" {
  display_name = "Device Support"
  description  = "Read devices, groups and applications, and read BitLocker key metadata"
  is_enabled   = true
  template_id  = "d5b6a8c4-3f2e-4a1b-9c7d-2e8f6a4b1c3d"
  version      = "1"

  role_permissions = [
    {
      allowed_resource_actions = [
        "microsoft.directory/applications/standard/read",
        "microsoft.directory/groups/standard/read"
      ]
    },
    {
      allowed_resource_actions = [
        "microsoft.directory/devices/standard/read",
        "microsoft.directory/bitlockerKeys/metadata/read"
      ]
    }
  ]

  timeouts = {
    create = "180s"
    read   = "180s"
    update = "180s"
    delete = "180s"
  }
}
```

## Important Notes

### Custom Roles Only

- This resource manages custom Microsoft Entra directory roles. Built-in roles cannot be imported or managed; read them with the role definitions data source instead.
- Custom directory roles require a Microsoft Entra ID P1 or P2 licence.

### Resource Actions

- Every action must belong to the `microsoft.directory` namespace, for example `microsoft.directory/applications/standard/read`.
- Actions are checked against the live `microsoft.directory` action catalogue before any write. Microsoft Entra silently rewrites some unknown actions (for example `applications/basic/read` becomes `applications/standard/read`), which would cause permanent drift, so unknown actions are rejected with an error.
- List the valid actions with `GET /roleManagement/directory/resourceNamespaces/microsoft.directory/resourceActions`.

### Template ID

- When `template_id` is set, Microsoft Entra uses it as the role definition ID. Changing it forces a new role.
- When it is not set, Microsoft Entra generates one and it matches `id`.

### Clearing Optional Values

- Removing `description` or `version` from configuration clears them in Microsoft Entra.

### Eventual Consistency

- A new role can return 404 for several seconds after creation, and reads can be stale after an update. The provider retries reads until the written values are returned.

### Deletion

- Deleting a custom role is permanent; it is not moved to deleted items.
