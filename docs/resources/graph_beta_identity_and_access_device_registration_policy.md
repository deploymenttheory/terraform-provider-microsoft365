# microsoft365_graph_beta_identity_and_access_device_registration_policy (Resource)

Manages the tenant-wide Microsoft Entra device registration policy using the Microsoft Graph beta `/policies/deviceRegistrationPolicy` endpoint. The policy controls the device quota per user, multifactor authentication for device registration, Windows LAPS, and who can register (Microsoft Entra registered) or join (Microsoft Entra joined) devices.

This is a **singleton resource**: one policy exists per tenant. `create` adopts the existing policy and `create`/`update` apply the configuration with a full-replace PUT. Settings that are not configured keep their current tenant values, because the provider reads the policy before every PUT and sends unconfigured values back unchanged. On `destroy`, Terraform only removes the resource from state and leaves the tenant policy as it is. Manage only one instance per tenant across all Terraform states.

## Example Usage

### Minimal Configuration

```terraform
# Manage only the device quota. Every other setting keeps its current tenant value.
resource "microsoft365_graph_beta_identity_and_access_device_registration_policy" "example" {
  user_device_quota = 50
}
```

### Complete Configuration

```terraform
# Manage every device registration setting.
# When Microsoft Intune is enabled, azure_ad_registration cannot be changed and must match the
# current tenant value (usually "all"), or be left out.
resource "microsoft365_graph_beta_identity_and_access_device_registration_policy" "example" {
  user_device_quota               = 20
  multi_factor_auth_configuration = "required"

  local_admin_password = {
    is_enabled = true
  }

  azure_ad_registration = {
    allowed_to_register = {
      type = "all"
    }
  }

  azure_ad_join = {
    allowed_to_join = {
      type = "all"
    }
    local_admins = {
      enable_global_admins = true
      registering_users = {
        type = "none"
      }
    }
  }
}
```

### Restrict Microsoft Entra Join to a Group

```terraform
# Allow only members of a group to join devices to Microsoft Entra ID.
resource "microsoft365_graph_beta_groups_group" "device_joiners" {
  display_name     = "Device Joiners"
  mail_nickname    = "device-joiners"
  mail_enabled     = false
  security_enabled = true
  description      = "Users allowed to join devices to Microsoft Entra ID"
}

resource "microsoft365_graph_beta_identity_and_access_device_registration_policy" "example" {
  azure_ad_join = {
    allowed_to_join = {
      type   = "enumerated"
      groups = [microsoft365_graph_beta_groups_group.device_joiners.id]
    }
  }
}
```

## Important Notes

- **Singleton Resource**: One device registration policy exists per tenant. Manage one instance per tenant across all Terraform states. The ID is always `deviceRegistrationPolicy`.
- **Create and Update Behavior**: Create adopts the existing tenant policy. Both create and update read the current policy and then replace it with a full PUT, because Graph requires every updatable property on PUT.
- **Destroy Behavior**: Destroy only removes the resource from Terraform state. The tenant device registration policy is left unchanged; it is not reset to defaults.
- **Unconfigured Settings**: Every setting is optional. Settings that are not configured keep their current tenant values, which are read before every PUT and sent back unchanged.
- **Memberships**: `allowed_to_register`, `allowed_to_join` and `registering_users` take a `type` of `all`, `none` or `enumerated`. `users` and `groups` are only valid with `enumerated`; an unset list is omitted from the request.
- **Intune and Microsoft Entra registration**: When Microsoft Intune is enabled in the tenant, Graph reports `azure_ad_registration.is_admin_configurable = false` and ignores changes to `allowed_to_register`. The provider sends the current value back and returns an error if the configuration asks for a different value.
