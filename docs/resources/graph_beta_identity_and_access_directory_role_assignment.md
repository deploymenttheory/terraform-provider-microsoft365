# microsoft365_graph_beta_identity_and_access_directory_role_assignment (Resource)

Manages a permanent active Microsoft Entra directory role assignment at tenant scope using Microsoft Graph beta `/roleManagement/directory/roleAssignments`. This grants active access; it does not create PIM eligibility or a scheduled assignment. Changing the role or principal replaces the assignment.

## Microsoft Documentation

- [Directory role assignment](https://learn.microsoft.com/en-us/graph/api/resources/unifiedroleassignment?view=graph-rest-beta)
- [Create assignment](https://learn.microsoft.com/en-us/graph/api/rbacapplication-post-roleassignments?view=graph-rest-beta)
- [Get assignment](https://learn.microsoft.com/en-us/graph/api/unifiedroleassignment-get?view=graph-rest-beta)
- [Delete assignment](https://learn.microsoft.com/en-us/graph/api/unifiedroleassignment-delete?view=graph-rest-beta)

## Microsoft Graph API Permissions

Reading requires application permission `RoleManagement.Read.Directory`. Writing requires `RoleManagement.ReadWrite.Directory`, which also permits reading.

## Example Usage


## Important Notes

- This resource creates a permanent active assignment at tenant scope `/`. It does not configure PIM eligibility, scheduling, administrative-unit scope, or application scope.
- Supply a built-in role **template ID** or custom **role definition ID**. An activated `directoryRole.id` is a different identifier.
- The principal must be a user, service principal, or group that supports role assignment.
- Assignment identity is immutable. Changing the role or principal replaces the assignment. Existing assignments must be imported; creation does not silently adopt duplicates.
- Import uses the opaque Graph assignment ID, which is not necessarily a UUID. Assignments outside tenant scope are rejected on read/import.
- Destroy deletes the assignment itself and confirms its absence before removing Terraform state. It does not delete the principal or role definition.
