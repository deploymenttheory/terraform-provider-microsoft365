# microsoft365_graph_beta_device_management_mobile_threat_defense_connector (Resource)

Manages an Intune Mobile Threat Defense partner connector using the `/deviceManagement/mobileThreatDefenseConnectors` endpoint. The connector ID is the fixed partner ID of the Mobile Threat Defense partner (for example `fc780465-2017-40d4-a0c5-307022471b92` for Microsoft Defender for Endpoint). Creating the resource posts the full connector configuration for that partner, which replaces any settings already present for the partner, and destroying it deletes the connector.

## Example Usage

### Microsoft Defender for Endpoint

```terraform
# Microsoft Defender for Endpoint connector.
# The connector ID is the fixed partner ID of Microsoft Defender for Endpoint.
# If the tenant already has this connector (the "Microsoft Intune connection" is
# turned on in the Microsoft Defender portal), import it first so Terraform
# manages the existing settings instead of replacing them on create.
resource "microsoft365_graph_beta_device_management_mobile_threat_defense_connector" "microsoft_defender" {
  id = "fc780465-2017-40d4-a0c5-307022471b92"

  # Use partner data in compliance evaluations
  android_enabled = true
  ios_enabled     = true
  mac_enabled     = false
  windows_enabled = true

  # Use partner data in app protection (MAM) evaluations
  android_mobile_application_management_enabled = true
  ios_mobile_application_management_enabled     = true
  windows_mobile_application_management_enabled = false

  # Compliance behaviour
  partner_unsupported_os_version_blocked     = true
  partner_unresponsiveness_threshold_in_days = 7

  # iOS/iPadOS metadata collection
  allow_partner_to_collect_ios_application_metadata          = true
  allow_partner_to_collect_ios_personal_application_metadata = false
  allow_partner_to_collect_ios_certificate_metadata          = false
  allow_partner_to_collect_ios_personal_certificate_metadata = false

  # Defender for Endpoint only: configuration profile management through Defender
  microsoft_defender_for_endpoint_attach_enabled = true

  timeouts = {
    create = "180s"
    read   = "180s"
    update = "180s"
    delete = "180s"
  }
}
```

### Third-Party Partner

```terraform
# Third-party Mobile Threat Defense partner connector (Lookout for Work).

  id = "2c7790de-8b02-4814-85cf-e0c59380dee8"

  android_enabled = true
  ios_enabled     = true

  partner_unsupported_os_version_blocked     = false
  partner_unresponsiveness_threshold_in_days = 14

  allow_partner_to_collect_ios_application_metadata = true
}
```

## Important Notes

### Connector IDs

- The connector ID is the partner ID. Each Mobile Threat Defense partner has a fixed ID that is the same in every tenant, and Graph rejects IDs that do not belong to a supported partner.
- Microsoft Defender for Endpoint uses `fc780465-2017-40d4-a0c5-307022471b92`.
- Changing `id` replaces the resource: the old partner's connector is deleted and a connector for the new partner is created.

### Create, Adopt and Delete

- Graph treats the create request as an upsert keyed on the partner ID. Creating this resource for a partner that already has a connector replaces that connector's settings with the configured values, including the defaults for any setting left unset.
- To bring an existing connector under management without changing it first, import it and copy its current settings into the configuration.
- Destroying the resource deletes the connector. For Microsoft Defender for Endpoint this removes the Intune side of the Defender connection; turning the "Microsoft Intune connection" setting off and on again in the Microsoft Defender portal recreates it with default settings. Remove the resource from state instead (`terraform state rm` or a `removed` block) if the connector must stay in the tenant.
- Graph returns success when deleting a connector that does not exist.

### Read-Only Settings

- `android_device_blocked_on_missing_partner_data`, `ios_device_blocked_on_missing_partner_data`, `mac_device_blocked_on_missing_partner_data` and `windows_device_blocked_on_missing_partner_data` are derived by Graph from the matching `*_enabled` setting and ignore writes, so they are read-only.
- `partner_state` and `last_heartbeat_date_time` are set by the service. A connector created for a partner that has not completed its connection from the partner console reports `partner_state = "notSetUp"` and no heartbeat.
- The `partner_*` capability attributes (supported MAM platforms and minimum OS versions) are reported by the service for the partner.

### Partner-Specific Settings

- `microsoft_defender_for_endpoint_attach_enabled` only applies to the Microsoft Defender for Endpoint connector. Graph returns `false` for other partners, so setting it to `true` for another partner produces an inconsistent result error.
- `launch_mobile_threat_defense_partner_on_setup_enabled` is ignored by partners that do not support it.
- Only one partner per platform may be enabled for Mobile Application Management (MAM) evaluation. Check the other connectors in the tenant before enabling `*_mobile_application_management_enabled`.
