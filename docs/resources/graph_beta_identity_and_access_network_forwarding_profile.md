# microsoft365_graph_beta_identity_and_access_network_forwarding_profile (Resource)

Manages a custom Microsoft Entra Global Secure Access traffic forwarding profile (traffic forwarding profile v2) using Microsoft Graph beta `/networkaccess/forwardingProfiles`. The tenant must use traffic forwarding profiles v2. Destroy deletes the profile. Use `microsoft365_graph_beta_identity_and_access_network_default_forwarding_profile` for the built-in profiles. Policy links and remote network associations are not managed by this resource.

## Prerequisites

The tenant must use traffic forwarding profiles v2 (Global Secure Access > Connect > Traffic forwarding). Switching to v2 cannot be undone. Custom profiles require the latest Global Secure Access client.

## Considerations

- Graph currently allows custom profiles only for `private` traffic. `internet` and `m365` return an error until Microsoft enables multiple profiles for the tenant.
- Custom private profiles use priorities 101-200 and every priority must be unique in the tenant. The default private profile uses 200. Up to 10 custom private profiles are supported during preview.
- `local_network_settings` enables [home network support](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-configure-home-network-support) (preview). It applies to directly connected IPv4 RFC 1918 subnets only and is not supported on mobile clients.
- `assignment_rules` replaces all assignments. Graph rejects device IDs passed as users or groups (and vice versa), and returns HTTP 500 for IDs that do not exist.
- Graph can return HTTP 504 after it has created a profile. The resource then adopts the custom profile with the planned name, type and priority instead of failing.
- Private Access applications, Private DNS policies and remote networks are linked to profiles separately and are not managed by this resource.

## Microsoft Graph API Permissions

- Read / Write (application): `NetworkAccess.ReadWrite.All`, verified in live testing.

The v2 profile properties are not documented in the Microsoft Graph reference. The request shapes follow the Microsoft Entra admin center.

## Example Usage

```terraform
# Custom Private Access profile with home network support. Users assigned to
# this profile can turn on "Prefer Local Network" in the Global Secure Access
# client to reach devices on their directly connected local subnet.
resource "microsoft365_graph_beta_identity_and_access_network_forwarding_profile" "home_network" {
  name                    = "Private Access - remote workers"
  description             = "Private Access with home network support"
  traffic_forwarding_type = "private"
  priority                = 150
  state                   = "enabled"
  client_fallback_action  = "bypass"

  local_network_settings = {
    allow_local_subnet_bypass = true
  }

  forwarding_source_matching = {
    session_type = "any"
  }

  assignment_rules = {
    membership = "enumerated"
    group_ids  = ["00000000-0000-0000-0000-000000000001"]
    platforms  = ["windows", "macOS"]
  }
}
```
