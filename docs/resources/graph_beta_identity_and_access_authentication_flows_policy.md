# microsoft365_graph_beta_identity_and_access_authentication_flows_policy (Resource)

Manages the tenant-wide Microsoft Entra authentication flows policy using the Microsoft Graph beta `/policies/authenticationFlowsPolicy` endpoint.

This is a **singleton resource** — one policy exists per tenant. Create and update use PATCH to configure the existing policy. On destroy, Terraform removes the resource from state only, leaving the policy unchanged. Manage only one instance per tenant across all Terraform states.

## Microsoft Documentation

- [authenticationFlowsPolicy resource type](https://learn.microsoft.com/en-us/graph/api/resources/authenticationflowspolicy?view=graph-rest-beta)
- [Get authenticationFlowsPolicy](https://learn.microsoft.com/en-us/graph/api/authenticationflowspolicy-get?view=graph-rest-beta&tabs=http)
- [Update authenticationFlowsPolicy](https://learn.microsoft.com/en-us/graph/api/authenticationflowspolicy-update?view=graph-rest-beta&tabs=http)

## Microsoft Graph API Permissions

## Important Notes

- **Singleton Resource**: Manage one instance per tenant across all Terraform states. The ID is always `authenticationFlowsPolicy`.
- **Create and Update Behavior**: Both operations use PATCH on `/policies/authenticationFlowsPolicy` to configure the existing policy, then GET to refresh state.
- **Destroy Behavior**: Only removes Terraform state. The policy and its settings remain in Microsoft Entra ID.
- **Boolean Settings**: `self_service_sign_up` and its `is_enabled` Boolean are required. Specify `true` or `false` explicitly.
- **Read-Only Metadata**: Microsoft Graph rejects changes to `displayName` and `description`. Their Terraform attributes are computed from GET responses.
