# microsoft365_graph_beta_applications_service_principal_token_signing_certificate (Resource)

Manages a token signing certificate for a Microsoft Entra Service Principal, used for SAML-based single sign-on. Microsoft Entra generates a self-signed certificate and adds the corresponding signing and verification key credentials (plus a password credential) to the service principal.

The certificate is immutable — changing any attribute forces recreation. For zero-downtime rotation, use `create_before_destroy` together with the `microsoft365_graph_beta_applications_service_principal_preferred_token_signing_key_thumbprint` resource, which activates the certificate and updates in place when the thumbprint changes.

For more information, see the [Microsoft Graph API documentation](https://learn.microsoft.com/en-us/graph/api/serviceprincipal-addtokensigningcertificate?view=graph-rest-beta).

- `Application.Read.All`
- `Application.ReadWrite.All`

**Optional:**

Find out more about the permissions required for managing service principals at Microsoft Learn [here](https://learn.microsoft.com/en-us/graph/api/resources/serviceprincipal?view=graph-rest-beta).

## Important Notes

- **Generated by Microsoft Entra**: The certificate is self-signed and generated server-side; the private key never leaves Microsoft Entra. Creation adds a signing key credential, a verification key credential, and a password credential to the service principal.
- **Immutable**: All configurable attributes force recreation. Rotate certificates with `create_before_destroy` and reference the new `thumbprint` from the `microsoft365_graph_beta_applications_service_principal_preferred_token_signing_key_thumbprint` resource, which updates in place.
- **Delete Behavior**: Destroying this resource removes the certificate's key credentials and password credential from the service principal via a read-modify-write PATCH of the credential lists. Avoid concurrent out-of-band modification of the same service principal's credentials, and avoid creating one certificate resource while destroying a *separate* certificate resource on the same service principal in a single apply (rotation of the *same* resource via `create_before_destroy` is safe — Terraform orders those operations).
- **Activation**: Generating a certificate does not activate it. Set `preferredTokenSigningKeyThumbprint` (via the companion resource) to make Microsoft Entra sign SAML tokens with it.

## Example Usage

```terraform
# Token signing certificate generated by Microsoft Entra for SAML single sign-on.
# Combine with the preferred token signing key thumbprint resource to activate it.

resource "microsoft365_graph_beta_applications_application" "example" {
  display_name     = "Example SAML Application"
  sign_in_audience = "AzureADMyOrg"
}

resource "microsoft365_graph_beta_applications_service_principal" "example" {
  app_id                        = microsoft365_graph_beta_applications_application.example.app_id
  preferred_single_sign_on_mode = "saml"
}

resource "microsoft365_graph_beta_applications_service_principal_token_signing_certificate" "example" {
  service_principal_id = microsoft365_graph_beta_applications_service_principal.example.id
  display_name         = "CN=Example SAML Signing"
  end_date_time        = "2028-01-01T14:59:59Z"

  # Create the replacement certificate before destroying the old one so the
  # preferred token signing key thumbprint can be rotated without downtime.
  lifecycle {
    create_before_destroy = true
  }
}

resource "microsoft365_graph_beta_applications_service_principal_preferred_token_signing_key_thumbprint" "example" {
  service_principal_id = microsoft365_graph_beta_applications_service_principal.example.id
  thumbprint           = microsoft365_graph_beta_applications_service_principal_token_signing_certificate.example.thumbprint
}
```
