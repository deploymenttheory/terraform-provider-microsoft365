# microsoft365_graph_beta_device_management_endpoint_security_intent (Resource)

Manages a template-based Intune endpoint security policy (intent) using the `/deviceManagement/intents` endpoint. An intent is created from a security template with `/deviceManagement/templates/{templateId}/createInstance`, its settings are changed with `/deviceManagement/intents/{id}/updateSettings` and its assignments are replaced with `/deviceManagement/intents/{id}/assign`. Microsoft is moving these templates to settings catalog configuration policies, so this resource is mainly for managing existing estates; new policies should use the settings catalog where the template has been migrated.

## Example Usage

### Minimal

```terraform
# BitLocker disk encryption intent with the template defaults
resource "microsoft365_graph_beta_device_management_endpoint_security_intent" "bitlocker_minimal" {
  template_id  = "d1174162-1dd2-4976-affc-6667049ab0ae"
  display_name = "BitLocker - template defaults"
}
```

### Maximal

```terraform
# BitLocker disk encryption intent with managed settings and assignments
resource "microsoft365_graph_beta_device_management_endpoint_security_intent" "bitlocker_maximal" {
  template_id        = "d1174162-1dd2-4976-affc-6667049ab0ae"
  display_name       = "BitLocker - encrypt devices"
  description        = "Require BitLocker and rotate recovery passwords for Entra joined devices"
  role_scope_tag_ids = ["0"]

  settings = [
    {
      definition_id = "deviceConfiguration--windows10EndpointProtectionConfiguration_bitLockerEncryptDevice"
      setting_type  = "boolean"
      value_json    = jsonencode(true)
    },
    {
      definition_id = "deviceConfiguration--windows10EndpointProtectionConfiguration_bitLockerRecoveryPasswordRotation"
      setting_type  = "string"
      value_json    = jsonencode("enabledForAzureAd")
    }
  ]

  assignments = [
    {
      type     = "groupAssignmentTarget"
      group_id = "00000000-0000-0000-0000-000000000001"
    },
    {
      type     = "exclusionGroupAssignmentTarget"
      group_id = "00000000-0000-0000-0000-000000000002"
    }
  ]

  timeouts = {
    create = "3m"
    read   = "3m"
    update = "3m"
    delete = "3m"
  }
}
```

## Important Notes

### Legacy Templates

- Intents are the template-based endpoint security policies. Microsoft is moving these templates to settings catalog configuration policies, which are managed with the settings catalog resources. Use this resource to manage existing intents, or templates that have not been migrated yet.
- List the templates available in a tenant with `GET /deviceManagement/templates`. The BitLocker template `d1174162-1dd2-4976-affc-6667049ab0ae` still accepted new intents when this resource was released.
- Changing `template_id` creates a new intent.

### Settings

- A new intent receives every setting of its template with the template default value. The resource only writes and tracks the settings listed in `settings`.
- `setting_type` must match the setting instance type Graph returns for the definition. Graph rejects the update when the generic setting type is sent.
- Find the definition IDs and types of a template by creating an intent in the Intune admin center and reading `GET /deviceManagement/intents/{id}/settings`.
- Settings changes are written with `updateSettings` and never recreate the intent.
- Removing a setting from `settings` stops managing it but does not reset it; it keeps its current value in Intune.
- `value_json` values that differ from Graph only in JSON formatting are not reported as drift.

### Assignments

- Assignments are replaced in full with the `assign` action. Removing the `assignments` attribute removes every assignment from the intent.

## Import

Import is supported using the following syntax. Add a slash and a comma-separated list of setting definition IDs to import the settings you want to manage, so the plan after import is empty:

```shell
# Import an intent by its ID. Settings are not tracked until they are added to configuration.
terraform import microsoft365_graph_beta_device_management_endpoint_security_intent.bitlocker_minimal 00000000-0000-0000-0000-000000000000

# Import an intent and the settings to manage, as a comma-separated list of setting definition IDs after a slash.
terraform import microsoft365_graph_beta_device_management_endpoint_security_intent.bitlocker_maximal 00000000-0000-0000-0000-000000000000/deviceConfiguration--windows10EndpointProtectionConfiguration_bitLockerEncryptDevice,deviceConfiguration--windows10EndpointProtectionConfiguration_bitLockerRecoveryPasswordRotation
```
