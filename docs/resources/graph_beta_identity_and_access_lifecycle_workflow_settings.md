# microsoft365_graph_beta_identity_and_access_lifecycle_workflow_settings (Resource)

Manages the tenant-wide Microsoft Entra ID Governance lifecycle workflow settings using the Microsoft Graph beta `/identityGovernance/lifecycleWorkflows/settings` endpoint. The settings control how often scheduled lifecycle workflows run and how lifecycle workflow email notifications are sent.

This is a **singleton resource**: one settings object exists per tenant. `create` adopts the existing settings and `create`/`update` apply the configuration with PATCH. Settings that are not configured keep their current tenant values. On `destroy`, Terraform only removes the resource from state and leaves the tenant settings as they are. Manage only one instance per tenant across all Terraform states.

## Example Usage

### Schedule Interval Only

```terraform
# Run scheduled lifecycle workflows every 6 hours.
# The email settings keep their current tenant values.
resource "microsoft365_graph_beta_identity_and_access_lifecycle_workflow_settings" "example" {
  workflow_schedule_interval_in_hours = 6
}
```

### Complete Configuration

```terraform
# Run scheduled lifecycle workflows every 12 hours and send email notifications
# from a verified tenant domain using the company branding.
resource "microsoft365_graph_beta_identity_and_access_lifecycle_workflow_settings" "example" {
  workflow_schedule_interval_in_hours = 12

  email_settings = {
    # Must be a verified domain of the tenant, written exactly as in the tenant domain list.
    # Use "microsoft.com" to send from the default Microsoft sender.
    sender_domain        = "contoso.com"
    use_company_branding = true
  }

  timeouts = {
    create = "5m"
    read   = "5m"
    update = "5m"
    delete = "5m"
  }
}
```

## Important Notes

### Singleton Resource
- One lifecycle workflow settings object exists per tenant. It cannot be created or deleted.
- `create` adopts the existing settings and applies the configured values with `PATCH`.
- `destroy` only removes the resource from Terraform state; the tenant settings keep their current values.
- Manage only one instance per tenant across all Terraform states.

### Unconfigured Values
- `workflow_schedule_interval_in_hours`, `email_settings`, `email_settings.sender_domain` and `email_settings.use_company_branding` are all optional.
- A value that is not configured keeps its current tenant value and is not sent to Graph.
- When a configuration stops managing a value, the value that was last applied stays in place.

### Schedule Interval
- `workflow_schedule_interval_in_hours` sets how often all scheduled workflows run and must be between `1` and `24`. Graph rejects other values.

### Sender Domain
- `microsoft.com` is the default sender domain and sends notifications from the Microsoft sender.
- Any other `sender_domain` must be a verified domain of the tenant. Graph compares the value case-sensitively with the tenant domain list, so write it exactly as it appears there (for example `Contoso.onmicrosoft.com`), otherwise Graph returns `400 Provided domain is not verified for tenant or is not an eligible domain`.

### Not Managed
- `quarantineConfiguration` is returned by Graph but is not managed by this resource and is left unchanged.
