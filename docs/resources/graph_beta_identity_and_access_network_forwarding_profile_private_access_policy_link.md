# microsoft365_graph_beta_identity_and_access_network_forwarding_profile_private_access_policy_link (Resource)

Links one Global Secure Access Private Access forwarding policy (app or DNS policy) to a private forwarding profile using the `policies@delta` collection of `/networkAccess/forwardingProfiles/{id}` or `/networkAccess/deviceForwardingProfiles/{id}`. Graph only supports adding and removing links, so every argument forces replacement.

## Microsoft Graph API

This resource uses Microsoft Graph beta:

- Read: `GET /networkAccess/forwardingProfiles/{id}?$expand=policies($expand=policy)` (or `/networkAccess/deviceForwardingProfiles/{id}` when `profile_type = "device"`).
- Create and destroy: `PATCH` the same profile with a `policies@delta` entry that adds the link, or removes it with `@removed`.

## Microsoft Graph API Permissions

The following client `application` permissions are needed in order to use this resource:

**Required:**
- `NetworkAccess.Read.All`
- `NetworkAccess.ReadWrite.All`

**Optional:**
- `None` `[N/A]`

## Behavior Notes

- Graph only supports adding and removing forwarding policy links. Updating a link's `priority` or `state` is rejected, so every argument forces replacement.
- When a new custom user forwarding profile is created, Microsoft automatically links the tenant's existing Private Access app policies (priority `65000`, `enabled`). If the configured policy is already linked with the configured `state` and `priority` (or `priority` is omitted), create adopts that link without writing. Otherwise the existing link is removed and re-added with the configured values. Removed automatic links are not recreated by Microsoft. Device forwarding profiles start with no links.
- Graph rejects removing and re-adding the same policy in one request, so replacement uses two `PATCH` requests and waits for the removal to propagate in between. A new `policy_link_id` is issued each time.
- If the link is re-added outside Terraform, the resource finds it again by `forwarding_policy_id` and updates `policy_link_id`.
- Links are eventually consistent; create and destroy wait for three consecutive matching reads.
- The Entra admin center offers priorities 100-64999. Graph also accepts other values up to `65000`.
- `config_type = "dnsPolicy"` sends the same payload as `appPolicy` but has not been verified against a live tenant.
- Do not manage the same link with both this resource and `microsoft365_graph_beta_identity_and_access_network_forwarding_profile_policy_link`. That resource adopts Microsoft-created links and only toggles `state`; destroying it does not remove the link.

## Example Usage

```terraform
# Link a Private Access app policy to a custom user forwarding profile.
resource "microsoft365_graph_beta_identity_and_access_network_forwarding_profile_private_access_policy_link" "app" {
  forwarding_profile_id = "00000000-0000-0000-0000-000000000001"
  forwarding_policy_id  = "00000000-0000-0000-0000-000000000002"
  config_type           = "appPolicy"
  priority              = 120
  state                 = "enabled"

  timeouts = {
    create = "5m"
    delete = "5m"
  }
}

# Link a Private Access app policy to a pre-logon (device) forwarding profile.
resource "microsoft365_graph_beta_identity_and_access_network_forwarding_profile_private_access_policy_link" "device" {
  forwarding_profile_id = "00000000-0000-0000-0000-000000000003"
  profile_type          = "device"
  forwarding_policy_id  = "00000000-0000-0000-0000-000000000002"
  config_type           = "appPolicy"
}
```

## Schema

### Required

- `config_type` (String) Link configuration type. Possible values are `appPolicy` and `dnsPolicy`. `dnsPolicy` uses the same payload as `appPolicy` but has not been verified against a live tenant.
- `forwarding_policy_id` (String) ID of the Private Access forwarding policy to link. This is the forwardingPolicy ID, not the application or service principal ID.
- `forwarding_profile_id` (String) ID of the private forwarding profile to link the policy to.

### Optional

- `priority` (Number) Link priority. The Entra admin center offers 100-64999; Graph also accepts other values up to 65000, which is what automatically created links receive. When omitted, Graph assigns it.
- `profile_type` (String) Forwarding profile kind. `user` (default) targets `/networkAccess/forwardingProfiles`; `device` targets the pre-logon `/networkAccess/deviceForwardingProfiles`.
- `state` (String) Link state. Possible values are `enabled` (default) and `disabled`.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `id` (String) Terraform identifier in `{forwarding_profile_id}/{policy_link_id}` format.
- `policy_link_id` (String) ID of the forwardingPolicyLink object. Graph issues a new ID whenever the link is removed and re-added.
