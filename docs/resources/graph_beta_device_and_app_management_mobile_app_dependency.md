# microsoft365_graph_beta_device_and_app_management_mobile_app_dependency (Resource)

Manages a dependency between two Microsoft Intune Win32 apps. The source app requires the target app to be detected or automatically installed before its own installation. Each resource manages one dependency and preserves other app relationships.

## Microsoft Documentation

- [mobileAppDependency resource type](https://learn.microsoft.com/en-us/graph/api/resources/intune-apps-mobileappdependency?view=graph-rest-beta)
- [updateRelationships action](https://learn.microsoft.com/en-us/graph/api/intune-apps-mobileapp-updaterelationships?view=graph-rest-beta)
- [Win32 app dependencies](https://learn.microsoft.com/en-us/intune/intune-service/apps/apps-win32-add#step-5-dependencies)

## Example Usage

```terraform
# Automatically install a prerequisite before the application that needs it.
resource "microsoft365_graph_beta_device_and_app_management_mobile_app_dependency" "runtime" {
  source_id       = "00000000-0000-0000-0000-000000000001" # Application that requires the runtime
  target_id       = "00000000-0000-0000-0000-000000000002" # Prerequisite runtime app
  dependency_type = "autoInstall"

  timeouts = {
    create = "5m"
    read   = "5m"
    update = "5m"
    delete = "5m"
  }
}

# Require an existing prerequisite without installing it automatically.
resource "microsoft365_graph_beta_device_and_app_management_mobile_app_dependency" "existing_prerequisite" {
  source_id       = "00000000-0000-0000-0000-000000000003"
  target_id       = "00000000-0000-0000-0000-000000000004"
  dependency_type = "detect"
}
```

## Important Notes

- **Win32 Apps**: Both apps must be Intune Win32 apps. The `source_id` identifies the app that requires the prerequisite; the `target_id` identifies the prerequisite app.
- **Dependency Behavior**: Use `autoInstall` to automatically install the prerequisite or `detect` to require an existing installation.
- **Relationship Management**: Each resource manages one dependency. The provider uses `updateRelationships` and preserves other outgoing dependencies and supersedence relationships.
- **Updates**: Changing `dependency_type` updates the dependency in place. Changing `source_id` or `target_id` replaces it.
- **Concurrent Changes**: Dependency writes for the same source app are serialized within a provider process.
- **Import**: Import the actual relationship ID returned by Microsoft Graph. Graph supplies the source and target app IDs during import.
